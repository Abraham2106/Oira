Cómo se escoge y se usa la GPU

Hay dos decisiones independientes. Chromium pide una GPU para dibujar la ventana. El worker QVAC pide otra para Whisper y Qwen. El cómputo de modelos se ejecuta en el worker Bare mediante la selección GPU predeterminada del SDK; el backend efectivo se registra tras cargar. La AMD integrada no recibe modelos.

Ver GPU 0 junto a Oira.exe no demuestra que la inferencia use la integrada. Optimus puede presentar la imagen por la iGPU aunque la RTX calcule. La evidencia es backendDevice: "gpu" y la memoria NVIDIA en nvidia-smi.

Mapa de procesos

Carril A — ventana

apps/desktop/src/main/index.ts añade force_high_performance_gpu antes de app.whenReady(). Es una preferencia DXGI de alto rendimiento para Chromium. No selecciona el adaptador Vulkan del worker.

Carril B — inferencia

composeApplication → createInferencePorts("qvac") → createQvacInferenceRuntime. Un solo modelo residente: Whisper o Qwen. El renderer solo ve eventos de ciclo de vida.

Cómo se escoge

Inventario. getSystemResources({ sample: true }) vía getSystemResources. Los datos de hardware son diagnósticos; el SDK conserva la decisión de backend y la VRAM puede ser unverified.
Parseo. extractGpusFromSystemResources guarda el índice QVAC (posición en el array) y metadatos de backend. Archivo: src/main/qvac/device-selection.ts.
Sin filtro duro. El probe informa el panel de diagnóstico, pero nunca bloquea la carga. El SDK elige el backend predeterminado.
Diagnóstico. Si se muestran adaptadores, se ordenan por VRAM; el índice no se pasa al modelo. Qwen y Whisper usan defaults del SDK.

Cómo comprobar la RTX

Aprovisionar ambos pesos en %APPDATA%\Oira\model-cache y:

node apps/desktop/scripts/qvac-packaged-gpu-smoke.mjs "$env:LOCALAPPDATA\Oira\app-0.0.7\Oira.exe"

Debe terminar en PACKAGED_SMOKE_PASS, con backendDevice: "gpu" y memoria RTX al alza en nvidia-smi.
